# Pokédex Search

A search for the first 151 Pokémon that understands what you mean: type part of a name, a typo, criteria ("fast electric") or an effect in your own words ("put my opponent to sleep"), and get ranked results showing what matched. The search runs in the browser, for free. An AI search is there as an option.

**Live: https://prof-chen.vercel.app/** · **Search evaluation, live: https://prof-chen.vercel.app/eval**

## Try these

- `bulba`: part of a name
- `fast electric`: criteria
- `put my opponent to sleep`: an effect in your own words
- `rain team`: a theme across Pokémon, moves and abilities
- `make the enemy doze off`: search by meaning

The Pokémon dataset provided with the exercise (Pokémon #1–151 with their moves and abilities, generated by Biolevate from [PokeAPI](https://pokeapi.co/)).

### To use LLM search locally

By default, the search using LLMs is disabled unless you have an api key. To test it, you'll need an Anthropic API key.

Copy `.env.example` to `.env.local` and set `ANTHROPIC_API_KEY`. Optional: `AI_MODEL` (default `claude-haiku-5-5`) and `AI_THINKING` (empty = thinking off; `enabled` turns it on).

- **Safety:** the key stays on the server (CI fails if one is committed), and queries go to Anthropic only when you press the button.
- **Cost:** about 0.82 € per 1,000 queries with Claude Haiku 5.5 when the cache is warm, more with sparse traffic. There's no usage limit in the code; spending is capped in the Anthropic console.

## How it works

Three layers, from cheapest to most expensive:

1. **Deterministic search**, always on: names, typos, types, criteria and effects, each result scored from 0 to 1. Effects come from a concept dictionary that knows their direction (Hypnosis puts the target to sleep, Insomnia prevents it).
2. **Search by meaning**, when no result is confident (score below 0.7): a small embedding model (33 MB) runs in a Web Worker in the browser, so typing never waits.
3. **LLM search**, optional: a button sends the query to an LLM (Claude Haiku 5.5) through a server route. When the search isn't sure, the app suggests it: "Not what you're looking for? Let AI help you". It's never called on its own. Off without an API key, and the rest of the app doesn't change.

Details: [docs/03-tech-spec.md](./docs/03-tech-spec.md).

## How good is it

192 test queries, each with its expected answers, from four sources: the brief (9), a real user's searches (12), common search patterns found online (51) and cases drafted with AI from the data (120). Every engine runs on the same cases.

**The free app passes 74%. With an LLM as the fallback for the queries it isn't sure about, 93%.**

| Engine                                                      | Cases passed  | Best answer first | Order of the top 10 (nDCG) | Typical time                       | Cost per 1,000 queries |
| ----------------------------------------------------------- | ------------- | ----------------- | -------------------------- | ---------------------------------- | ---------------------- |
| Deterministic                                               | 137 (71%)     | 74%               | 0.77                       | 11 ms                              | 0 €                    |
| Embeddings only                                             | 34 (18%)      | 19%               | 0.18                       | 7 ms                               | 0 €                    |
| **Hybrid (deterministic + embeddings): the app without AI** | **143 (74%)** | **78%**           | **0.82**                   | **14 ms**                          | **0 €**                |
| Deterministic + LLM fallback (Haiku 5.5)                    | **178 (93%)** | 93%               | 0.95                       | 24 ms (1.3 s when it asks the LLM) | 0.38 €                 |
| LLM alone: Claude Haiku 5.5                                 | 151 (79%)     | 85%               | 0.88                       | 1.3 s                              | 0.82 €                 |
| Claude Code (Opus 5.5, reference)                           | 179 (93%)     | 95%               | 0.94                       | not timed                          | not measured           |

Claude Code (reference) is an upper bound: answers written once by a Claude Code session that saw the full data. What the numbers mean, where the cases come from and how they were checked: [docs/05-evaluation.md](./docs/05-evaluation.md).

## Choices, limits and next steps

**Choices**

- **Deterministic first.** Most searches are names, typos, types and numbers, where rules are exact, instant and explainable. Every result shows what matched.
- **Meaning as a fallback, in the browser.** When the rules aren't confident, a small local model compares the meaning of the query with the move, ability and Pokémon descriptions, for free, offline, with no key.
- **AI as an option, measured.** The LLM is better on descriptions and full sentences but slower and paid, so it's a button, and the eval shows the trade-off in numbers.

**Limits** (more in [docs/06-write-up.md](./docs/06-write-up.md))

- The test cases are development data now: I fixed the search against them. A fresh set from new users is the real test.
- Describing a Pokémon and lore questions are weak without the LLM (40% → 95% with it on "identify from a description").
- Some noise still finds something ("hello" → yellow).
- No type chart, so no "best counter for Gyarados".

**Next:** a blind test set from new users · the LLM fallback on a smaller catalogue (faster, cheaper) · a type chart for "how to beat X".
